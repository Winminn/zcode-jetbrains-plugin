# ZCode 桌面端实时联动 — 探索结论

> 创建时间：2026-08-13
> 状态：**已放弃实时联动方案**，插件走自足路线

---

## 一、结论

**ZCode 桌面端的会话列表是启动时的内存快照，整个进程生命周期内不会重新查询数据库。这是架构层面的设计，无法通过外部进程绕过。**

决策：**放弃实时联动**。插件做完整 UI（阶段 2 的 React 重构），自足运行，不依赖 ZCode 桌面端。ZCode 桌面端重启后能看到所有会话（数据持久），但实时同步不在当前架构可行范围内。

---

## 二、探索过的所有路径

### 2.1 数据库直接写入
- 直接往 `~/.zcode/cli/db/db.sqlite` 的 session 表写记录
- **结果**：ZCode 桌面端不刷新，看不到
- **原因**：桌面端启动时加载到内存，之后不查库

### 2.2 Chrome DevTools Protocol (CDP) 注入
- ZCode 带 `--remote-debugging-port=9222 --remote-allow-origins=*` 启动后可用 CDP 连上
- 能成功执行 JS（`Runtime.evaluate` 可用）
- **调用了以下 window.zcode 函数，均无法触发会话列表重新加载**：
  - `activateOrSetWorkspace()` — 只在已缓存会话间切换
  - `onOpenWorkspacePath()` — 不重新查库
  - `syncWindowTabs()` — 不重新查库
  - `onNewTask()` — 不重新查库
- **结果**：新创建的会话仍然不出现

### 2.3 文件监听 / TCP 端口
- ZCode 桌面端不监听任何 TCP 端口
- 源码无 fs.watch / chokidar（不监听文件变化）
- SQLite 无 update_hook / commit_hook
- webRemoteControl 走云端 relay（不是本地直连）
- **结果**：没有外部接入点

### 2.4 React 内部 API
- 理论上可以通过 CDP 找到 React Fiber 里的会话查询函数
- **未尝试**：极度脆弱，依赖混淆后的组件结构，ZCode 升级必断

## 三、技术发现（有价值，留作参考）

### CDP 连接方式（可复用于其他用途）
```bash
# 启动 ZCode 带 CDP 调试端口
"C:\...\ZCode.exe" --remote-debugging-port=9222 --remote-allow-origins=*
```
```javascript
// Node.js 连接（需 ws 库，绕过 origin 检查）
const ws = new WebSocket(wsUrl, { origin: 'chrome-extension://abc' });
ws.send(JSON.stringify({
    id: 1, method: 'Runtime.evaluate',
    params: { expression: '...', returnByValue: true }
}));
```

### window.zcode API 清单（90+ 个函数）
完整列表见探索日志。关键的：
- `activateOrSetWorkspace` — 切换 workspace
- `onNewTask` / `onOpenWorkspace` — 任务/workspace 回调
- `syncWindowTabs` / `syncWebRemoteControlTasks` — 同步函数
- `executeDesktopCommand` — 通用命令执行
- `startWebRemoteControl` / `stopWebRemoteControl` — 远程控制

这些函数都是 Electron preload 的 `contextBridge` 注入的（`[native code]`），源码在主进程侧不可见。

### SQLite 结构
- 路径：`~/.zcode/cli/db/db.sqlite`
- 模式：WAL（Write-Ahead Log）
- session 表字段：id, directory, path, title, time_created, time_updated, ...
- message / part / session_entry 等表存储消息和会话内容

## 四、对未来有价值的方向

如果将来 ZCode 官方支持以下任一特性，实时联动可以重新评估：
1. **桌面端开 app-server 端口**（让第三方进程连入同一个状态机）
2. **桌面端加文件监听**（监听 db.sqlite 变化，自动刷新 UI）
3. **桌面端暴露 IPC 接口**（让外部进程发送"刷新"信号）

目前（ZCode 3.7.6 / CLI 0.16.3）都不支持。

---

## 五、对插件设计的影响

**无影响**。插件的架构本来就是自足的：
- 插件自己有 app-server 进程（完整会话生命周期）
- 插件自己有 UI（阶段 2 React 重构后会完整）
- 数据持久化到同一个 SQLite（重启 ZCode 可见）

用户使用模式：
- **在 IDEA 里**：用插件，实时操作，功能完整
- **在 ZCode 桌面端**：重启后能看到所有会话（包括插件创建的），作为"查看历史"的补充工具

这是一个**合理的分工**，不是缺陷。
