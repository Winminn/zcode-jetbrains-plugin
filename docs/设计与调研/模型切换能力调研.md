# ZCode 模型切换能力调研

> 调研日期：2026-08-13
> 调研目标：ZCode 客户端是否支持切换自定义模型？插件（IDEA 插件）有无接口可以切换模型？
> 结论先行：**ZCode 原生支持自定义模型，且协议层提供了完整的模型切换接口（会话级 + 工作区级），插件完全可以调用。项目已封装其中两个会话级接口。**

---

## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| ZCode 是否支持切换自定义模型？ | ✅ 支持。`~/.zcode/v2/config.json` 多 provider 注册表 + 内置模型目录 + 客户端设置 |
| 插件有无接口切换模型？ | ✅ 有，且不止一个。共 6 个模型相关协议方法（见 §3） |
| 项目当前已封装哪些？ | `session/setModel`、`session/updateRuntimeModelConfig`（`ZCodeProtocolClient.kt`） |
| 尚未封装、建议下一步封装？ | `workspace/upsertModelProvider`（注册自定义模型）、`workspace/setDefaultModel`（全局默认模型） |

## 2. ZCode 客户端侧：自定义模型机制（一手证据）

### 2.1 多 Provider 注册表 `~/.zcode/v2/config.json`

```json
{
  "provider": {
    "builtin:bigmodel-coding-plan": {
      "name": "BigModel - Coding Plan",
      "kind": "anthropic",
      "options": {},
      "enabled": true,
      "source": "custom",
      "models": {}
    },
    "27d2ecde-5da2-43bd-b2d8-dae985bfaf8f": {
      "name": "DeepSeek",
      "kind": "anthropic",
      "options": {},
      "source": "custom",
      "models": {}
    }
  }
}
```

- 每个 provider 有 `kind`（`anthropic` / `openai-compatible` 等）、`options.baseURL`、`options.apiKey`、`enabled` 开关、`source`（`builtin` / `custom` 等）
- 凭证注入环境变量三件套：`ZCODE_MODEL` / `ZCODE_BASE_URL` / `ANTHROPIC_API_KEY`（见 `protocol-client/.../Credentials.kt`）

### 2.2 内置模型目录（客户端打包下发）

`%LOCALAPPDATA%\Programs\ZCode\resources\model-providers\models_catalog_china_llm_zcode_2026-06-03.json`

- `schemaVersion: zcode.model-providers.v1`，内置 10 个 provider（Kimi/Moonshot、GLM、DeepSeek、Qwen 等）
- 每个 provider 定义 `endpoints.baseURL`、`defaultKind`（`anthropic` / `openai-compatible`）、`models[]`（id、kinds、modalities、contextWindow、maxOutputTokens、reasoning 档位）
- 即：**ZCode 内置了多家国产模型，且同一模型通常同时支持 anthropic 与 openai-compatible 两种协议**——这就是"自定义模型"的底层形态

### 2.3 客户端设置 `~/.zcode/v2/setting.json`

```json
"modelProviderFamilySelectedKeys": {
  "bigmodel": "coding-plan:builtin:bigmodel-coding-plan"
},
"modelProviderFamilyModes": { "bigmodel": "oauth" },
"providerFamilyDomain": "bigmodel"
```

- 客户端 UI 侧通过 `modelProviderFamilySelectedKeys` 记录每个 provider family 当前选中的 provider key
- 说明客户端 UI 的"切换模型"最终落点就是 provider 注册表 + 默认模型选择

## 3. 协议层：插件可用的模型接口（zcode.cjs 一手源码）

> 来源：`zcode.cjs` RPC 方法注册表与 zod schema（ZCode 13MB 打包源码，本机安装目录可复验）

### 3.1 方法总览

| 协议方法 | 作用域 | 参数（zod schema） | 项目现状 |
|---|---|---|---|
| `session/setModel` | 会话级 | `{sessionId, model: {providerId, modelId, variant?}, runtimeModel?, expectedRevision?, persistAsWorkspaceLastUsed?}` | ✅ 已封装 `setModel()` |
| `session/updateRuntimeModelConfig` | 会话级 | `{sessionId, runtimeModel: {revision, generatedAt, model, provider, thoughtLevel?}, applyModelSelection?}` | ✅ 已封装 `setRuntimeModelConfig()` |
| `session/setThoughtLevel` | 会话级 | `{sessionId, thoughtLevel, runtimeModel?, ...}` | ❌ 未封装 |
| `workspace/upsertModelProvider` | 工作区级 | `{workspace, provider: Provider, expectedWorkspaceRevision?}` | ❌ 未封装 |
| `workspace/removeModelProvider` | 工作区级 | `{workspace, providerId, expectedWorkspaceRevision?}` | ❌ 未封装 |
| `workspace/setDefaultModel` | 工作区级 | `{workspace, model: {providerId, modelId}, runtimeModel?, expectedWorkspaceRevision?}` | ❌ 未封装 |
| `workspace/updateProviderRegistry` | 工作区级 | `{workspace, registry: {revision, generatedAt, providers[]}, includeWorkspaceState?}` | ❌ 未封装 |

### 3.2 核心数据结构（zod schema 还原）

**模型引用 `$l`（modelRef）**
```json
{ "providerId": "string", "modelId": "string", "variant": "string?" }
```

**Provider `zNe`（自定义模型注册的核心）**
```json
{
  "providerId": "string",
  "kind": "anthropic | openai | openai-compatible",
  "apiFormat": "anthropic-messages | openai-chat-completions | openai-responses",
  "label": "string?",
  "source": "builtin | models-dev | custom | user | workspace | ephemeral",
  "baseURL": "string?",
  "apiKey": { "source": "credential|env|server-config|inline", "key"|"name"|"value": "..." },
  "apiKeyRequired": "boolean?",
  "headers": "{string: string}?",
  "providerOptions": "object?",
  "logoUrl": "string?",
  "modelsDevProviderId": "string?",
  "models": ["array<Model>, min 1"]
}
```

> 💡 `apiKey` 支持 `{source: "env", name: "XXX"}` 形式——**插件注册 provider 时不必传明文密钥，可以引用环境变量**，安全得多。

**Model `RHt`（models 数组元素）**
```json
{
  "modelId": "string",
  "label": "string?",
  "description": "string?",
  "contextWindow": "int?",
  "maxOutputTokens": "int?",
  "reasoning": "object?",
  "supportsImages": "boolean?",
  "supportsPdf": "boolean?",
  "supportsTools": "boolean?",
  "supportsStructuredOutput": "boolean?",
  "providerOptions": "object?"
}
```

**runtimeModel `T0`（updateRuntimeModelConfig 用）**
```json
{
  "revision": "string",
  "generatedAt": "string",
  "model": { "providerId": "string", "modelId": "string", "variant": "string?" },
  "provider": { "...同 zNe..." },
  "thoughtLevel": "string?"
}
```

### 3.3 服务端行为（handler 源码还原）

- **`workspace/upsertModelProvider`**：`normalizeProviderInput(provider)` 规范化 → `providers.set(providerId, provider)` → 清空 providerRevision → `revision++` → 同步 App → 发 `model_provider_upserted` 事件。→ **即"插件新增自定义模型"**
- **`workspace/removeModelProvider`**：`providers.delete(providerId)` + 删 secrets → 发 `model_provider_removed` 事件
- **`workspace/setDefaultModel`**：设置 `defaultModel` + `lastUsedModel`，若模型变更则清 `defaultThoughtLevel` → `revision++` → 发 `workspace_default_model_changed` 事件。→ **即"全局切换默认模型"**
- **`session/setModel`**：会话级切换，`persistAsWorkspaceLastUsed` 默认 true（切换会同步为工作区最近使用模型）
- **`session/updateRuntimeModelConfig`**：会话级全量替换运行时模型配置（model + provider + thoughtLevel），`applyModelSelection` 默认 true

## 4. 与现有项目的衔接

### 4.1 已封装（`ZCodeProtocolClient.kt:549-574`）

```kotlin
fun setModel(sessionId, modelId, providerId = "anthropic")        // session/setModel
fun setRuntimeModelConfig(sessionId, modelId, providerId, revision = "0") // session/updateRuntimeModelConfig
```

- `setModel` 当前用于修复 `-32031`（历史模型不可用）粘性错误
- 两处 `providerId` 默认值 `"anthropic"` 是简化假设——**真正切换时 providerId 应为目标 provider 的 ID（如 config.json 里的 key）**

### 4.2 建议下一步封装

1. **`workspace/upsertModelProvider`** —— 插件内"添加自定义模型"能力（baseURL + apiKey 引用 env + models 列表），与客户端 UI 的"添加自定义 Provider"等价
2. **`workspace/setDefaultModel`** —— 插件内"全局切换默认模型"
3. 若走会话级切换，注意 `-32031` 粘性坑：setModel 清不掉历史模型不可用状态，需配合新建/恢复会话（见 `MEMORY.md` 与 `send()` 的 fallback 逻辑）

### 4.3 已知坑提醒

- `session/updateRuntimeModelConfig` 的 `revision` 字段：规格书要求必须带（当前实现硬编码 `"0"`）
- 协议信封要求：请求不带 `jsonrpc` 字段；`session/subscribe` 必须先于 `send`（避免丢事件）—— 与现有客户端实现一致
- `apiKey` 优先用 `{source: "env"}` 引用，避免明文入协议日志
